# CI/CD Standards — Cure Consulting Group

When editing GitHub Actions workflows, follow these standards:

## Workflow Structure
- One workflow per concern: `ci.yml` (test + lint), `deploy.yml` (deploy), `release.yml` (version + publish)
- `concurrency` groups to cancel superseded runs on the same branch
- `timeout-minutes` on every job (30 for builds, 10 for lints)
- `workflow_call` reusable workflows — don't duplicate steps across files
- Pin runner images (`ubuntu-24.04`, `macos-26`), not `-latest`

## Supply Chain
- Pin every action to a full 40-character commit SHA with the tag in a trailing comment (`actions/checkout@<sha> # v7.0.1`); check the SHA belongs to the action's own repo, not a fork; let Dependabot or Renovate bump pins
- Workflow lockfiles (`.github/workflows/actions.lock`, generated by `gh actions-lock`) supersede SHA pins where adopted — public preview, GitHub Enterprise Cloud only since 2026-10-14; confirm before use

## Permissions & Secrets
- Top-level `permissions: { contents: read }` on every workflow; widen per job only where needed (`id-token: write` for OIDC, `pull-requests: write` for PR comments)
- `persist-credentials: false` on `actions/checkout` unless the job pushes
- OIDC for cloud auth (GCP Workload Identity Federation, AWS OIDC) — no long-lived keys
- Secrets only via `${{ secrets.* }}`; never echo them; `::add-mask::` for derived values
- Never interpolate untrusted `${{ github.event.* }}` input into `run:` — pass it through `env:`
- No `pull_request_target` job that checks out or runs the PR's code

## Caching & Performance
- Built-in caching in setup actions (or `actions/cache`)
- Matrix builds for cross-platform testing; parallelize independent jobs
- `actions/upload-artifact` / `download-artifact` to share outputs between jobs

## Quality Gates & Deploys
- Required checks before merge: lint, test, type-check, build; PR-only to main with required reviews
- Staging auto-deploys on merge to main; production behind an environment with required reviewers
- Roll back by revert commit or redeploying the last good build — not by hand; smoke tests after every deploy
